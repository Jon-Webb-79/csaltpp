\doxysubsection{Detailed Description}
Binary buddy memory allocator with power-\/of-\/two block management. 

\mbox{\hyperlink{classcslt_1_1BuddyAllocator}{Buddy\+Allocator}} implements the binary buddy memory allocation algorithm, which organizes memory into power-\/of-\/two sized blocks. When a block is freed, it attempts to coalesce (merge) with its \char`\"{}buddy\char`\"{} block to form larger free blocks, reducing fragmentation.

All allocations are rounded up to the nearest power-\/of-\/two size (including a 16-\/byte header). Memory is obtained directly from the OS via mmap() (POSIX) or Virtual\+Alloc() (Windows). The pool size is fixed at creation time.

Two blocks are \char`\"{}buddies\char`\"{} if they have the same size, are adjacent in memory, and their combined offset satisfies\+: offset XOR (2$^\wedge$order). When both buddies are free, they merge into a larger block, potentially triggering recursive coalescing up the size hierarchy.

Performance\+: O(log n) for allocation, deallocation, and coalescing, where n is the number of size levels. Memory overhead is $\sim$16 bytes per allocation for the header. This allocator is implemented on the heap. In order to drive compliance with MISRA standards, this class can be ommitted from compilation with the {\ttfamily STATIC ONLY} flag.

\begin{DoxyNote}{Note}
\mbox{\hyperlink{classcslt_1_1BuddyAllocator}{Buddy\+Allocator}} is not thread-\/safe. External synchronization required. 

Pool size is fixed at creation -\/ use \mbox{\hyperlink{classcslt_1_1BuddyAllocator_aa923e1e70ca1361b07780e973d0bc298}{reset()}} to clear or recreate for a different size. 

\mbox{\hyperlink{classcslt_1_1BuddyAllocator_ad73ade6bd9d847cf670eef2acb1a5258}{alloc()}} does not guarantee custom alignment -\/ use \mbox{\hyperlink{classcslt_1_1BuddyAllocator_a80193b4cc99ced2e692cf324df4f994b}{alloc\+\_\+aligned()}} for specific alignment requirements.
\end{DoxyNote}
\begin{DoxyWarning}{Warning}
Do not mix pointers from different allocators. 

All allocations become invalid when \mbox{\hyperlink{classcslt_1_1BuddyAllocator}{Buddy\+Allocator}} is destroyed.
\end{DoxyWarning}

Destructor for \mbox{\hyperlink{classcslt_1_1BuddyAllocator}{Buddy\+Allocator}}. 

The destructor is intentionally minimal and does NOT free the OS-\/backed memory pool or free-\/lists array. Cleanup is handled by the custom \mbox{\hyperlink{structcslt_1_1BuddyDeleter}{Buddy\+Deleter}} when the \mbox{\hyperlink{classcslt_1_1UniquePtr}{Unique\+Ptr}} goes out of scope.

\mbox{\hyperlink{classcslt_1_1BuddyAllocator}{Buddy\+Allocator}} instances are always managed via \mbox{\hyperlink{classcslt_1_1UniquePtr}{Unique\+Ptr}} with \mbox{\hyperlink{structcslt_1_1BuddyDeleter}{Buddy\+Deleter}}, which performs the actual resource cleanup in this order\+:
\begin{DoxyEnumerate}
\item Free OS-\/backed memory pool (via os\+\_\+free)
\item Free free-\/lists array (via delete\mbox{[}\mbox{]})
\item Call this destructor
\item Free \mbox{\hyperlink{classcslt_1_1BuddyAllocator}{Buddy\+Allocator}} structure (via \+::operator delete)
\end{DoxyEnumerate}

\begin{DoxyNote}{Note}

All outstanding allocations become invalid when the \mbox{\hyperlink{classcslt_1_1BuddyAllocator}{Buddy\+Allocator}} is destroyed. Accessing freed pointers results in undefined behavior.
\end{DoxyNote}

Allocates memory using the buddy allocation algorithm. The actual block size will be rounded up to the nearest power of 2 that can accommodate both the requested bytes and the internal 16-\/byte Buddy\+Header.

{\bfseries{Allocation Process\+:}}
\begin{DoxyEnumerate}
\item Calculate total size needed\+: bytes + sizeof(\+Buddy\+Header)
\item Round to next power of 2 (minimum\+: min\+\_\+block\+\_\+size)
\item Find free block of appropriate size (or larger)
\item Split larger blocks if necessary (recursive division by 2)
\item Place header at block start, return pointer after header
\item Optionally zero-\/initialize the user portion
\end{DoxyEnumerate}

{\bfseries{Block Sizing Example\+:}}
\begin{DoxyItemize}
\item Request 100 bytes → 100 + 16 (header) = 116 → rounds to 128 bytes
\item Request 256 bytes → 256 + 16 (header) = 272 → rounds to 512 bytes
\item Request 1000 bytes → 1000 + 16 (header) = 1016 → rounds to 1024 bytes
\end{DoxyItemize}

{\bfseries{Alignment\+:}} The returned pointer has natural alignment based on block position in the pool. It is NOT guaranteed to match base\+\_\+align from \mbox{\hyperlink{classcslt_1_1BuddyAllocator_a8b41015908b893bd2138d38399d86d3d}{Heap()}}. Use \mbox{\hyperlink{classcslt_1_1BuddyAllocator_a80193b4cc99ced2e692cf324df4f994b}{alloc\+\_\+aligned()}} for specific alignment requirements.

{\bfseries{Internal Fragmentation\+:}} Power-\/of-\/2 rounding creates internal fragmentation. A 100-\/byte request wastes $\sim$12 bytes within the 128-\/byte block (after accounting for header).

\begin{DoxyNote}{Note}
The returned pointer is NOT the start of the block. The block starts 16 bytes earlier with the Buddy\+Header.

The actual usable space may be larger than requested due to power-\/of-\/2 rounding, but you should only use the requested number of bytes.
\end{DoxyNote}

Allocates memory with a specific alignment guarantee. The allocation process is similar to \mbox{\hyperlink{classcslt_1_1BuddyAllocator_ad73ade6bd9d847cf670eef2acb1a5258}{alloc()}}, but allocates a larger block to ensure the user pointer can be positioned at the requested alignment.

{\bfseries{Allocation Process\+:}}
\begin{DoxyEnumerate}
\item Normalize alignment to power of 2 (e.\+g., 48 → 64)
\item Calculate total\+: bytes + header + (alignment -\/ 1) for worst-\/case padding
\item Round to next power of 2 (minimum\+: min\+\_\+block\+\_\+size)
\item Find and allocate block (with splitting if needed)
\item Find aligned position within block
\item Place header immediately before aligned position
\item Return aligned pointer
\end{DoxyEnumerate}

{\bfseries{Alignment Guarantee\+:}} The returned pointer is GUARANTEED to satisfy\+: reinterpret\+\_\+cast$<$uintptr\+\_\+t$>$(ptr) \% alignment == 0

{\bfseries{Block Sizing with Alignment\+:}}
\begin{DoxyItemize}
\item Request 256 bytes, 64-\/byte align → 256 + 16 + 63 = 335 → 512 bytes
\item Request 512 bytes, 256-\/byte align → 512 + 16 + 255 = 783 → 1024 bytes
\end{DoxyItemize}

{\bfseries{Overhead\+:}} Aligned allocations use more memory than \mbox{\hyperlink{classcslt_1_1BuddyAllocator_ad73ade6bd9d847cf670eef2acb1a5258}{alloc()}} due to\+:
\begin{DoxyItemize}
\item Larger block size to accommodate alignment padding
\item Potential unused space before and after user data
\end{DoxyItemize}

\begin{DoxyNote}{Note}
alignment=0 uses the platform\textquotesingle{}s natural alignment (alignof(max\+\_\+align\+\_\+t))

Non-\/power-\/of-\/2 alignments are automatically rounded up. For example, requesting 48-\/byte alignment will be rounded to 64 bytes.

The header is placed immediately before the aligned user pointer, NOT at the block start (unlike \mbox{\hyperlink{classcslt_1_1BuddyAllocator_ad73ade6bd9d847cf670eef2acb1a5258}{alloc()}}).
\end{DoxyNote}

{\bfseries{Initialization Process\+:}}

\item Initializes free-\/list array (one per size level)

\item min\+\_\+block\+\_\+size\+: Rounded up to next power of 2 (e.\+g., 100 → 128)
\item base\+\_\+align\+: Rounded up to next power of 2 (e.\+g., 48 → 64)
\item min\+\_\+block\+\_\+size adjusted to hold header + alignment if needed
\end{DoxyItemize}

{\bfseries{Size Levels\+:}} The number of free-\/list levels is\+: log2(pool\+\_\+size) -\/ log2(min\+\_\+block\+\_\+size) + 1 Example\+: pool=4096, min=64 → log2(4096) -\/ log2(64) + 1 = 12 -\/ 6 + 1 = 7 levels

Performs a non-\/throwing validation of a pointer against this allocator\textquotesingle{}s internal state. The function verifies that\+:


\begin{DoxyItemize}
\item {\ttfamily ptr} is non-\/null
\item {\ttfamily ptr} lies within the allocator\textquotesingle{}s managed memory pool
\item The internal Buddy\+Header immediately preceding {\ttfamily ptr} is readable
\item The header encodes a valid block order for this allocator
\item The block offset and size are consistent with the pool boundaries
\item {\ttfamily ptr} lies within the bounds of the referenced allocation block
\end{DoxyItemize}

This function is designed to be {\bfseries{memory-\/safe}}\+: it first performs a range check to ensure that reading the internal header cannot cause undefined behavior or a segmentation fault, even if {\ttfamily ptr} is invalid or foreign.

\begin{DoxyNote}{Note}
This function does NOT check whether the block is currently allocated or free; it only validates that the pointer is structurally consistent with a block that could have been allocated by this allocator.

Passing a pointer obtained from a different allocator instance will return false.

Passing an interior pointer (i.\+e., not the original user pointer returned by alloc/alloc\+\_\+aligned/realloc$\ast$) will return false.

The function is intentionally side-\/effect free and does not modify allocator state.
\end{DoxyNote}
\begin{DoxyWarning}{Warning}
A return value of true does not guarantee that the pointer has not already been freed or that the underlying memory has not been reused. Use-\/after-\/free remains undefined behavior.
\end{DoxyWarning}

\begin{DoxyReturn}{Returns}

Scans the allocator\textquotesingle{}s free lists from the largest block size down to the smallest and returns the size of the first non-\/empty free list encountered.

This value represents the {\bfseries{maximum single allocation}} that can currently succeed (ignoring internal header and alignment overhead).

Unlike \mbox{\hyperlink{classcslt_1_1BuddyAllocator_a1a05d4c28353926c6029ecd0f9f2080d}{remaining()}}, which reports total free capacity, this function accounts for {\bfseries{fragmentation}}. The function runs in O(\+L) time, where L is the number of size levels (log₂(pool\+\_\+size / min\+\_\+block\+\_\+size)).

\begin{DoxyNote}{Note}
The returned size is the raw block size managed by the buddy system. The actual maximum allocatable user payload may be smaller due to internal headers and alignment requirements.

The result may change immediately after any allocation or deallocation.
\end{DoxyNote}

{\em ptr} & Pointer to existing allocation (or nullptr) \\
\hline
{\em old\+\_\+bytes} & Current size of the allocation in bytes \\
\hline
{\em new\+\_\+bytes} & Desired new size in bytes \\
\hline
{\em zeroed} & If true, zero-\/initialize any newly allocated space (when growing)\\
\hline
\end{DoxyParams}
\begin{DoxyReturn}{Returns}
\mbox{\hyperlink{classcslt_1_1Expected}{Expected}} containing pointer to resized allocation on success, or error on failure
\end{DoxyReturn}
Resizes an existing allocation to a new size. The behavior depends on whether the allocation is growing, shrinking, or being created/freed.

{\bfseries{Special Cases\+:}}
\begin{DoxyItemize}
\item realloc(nullptr, 0, n) → Equivalent to alloc(n)
\item realloc(ptr, old, 0) → Frees ptr, returns nullptr (success)
\item realloc(ptr, 0, n) → \mbox{\hyperlink{classcslt_1_1Error}{Error}} (old\+\_\+bytes must be non-\/zero with valid ptr)
\end{DoxyItemize}

{\bfseries{Shrinking (new\+\_\+bytes $<$= current block capacity)\+:}}
\begin{DoxyItemize}
\item Returns same pointer (no reallocation)
\item Block is NOT split or resized (buddy system doesn\textquotesingle{}t support shrinking)
\item If zeroed=true and new\+\_\+bytes $>$ old\+\_\+bytes, zeros the extra space
\item Very fast (O(1)) -\/ no memory movement
\end{DoxyItemize}

{\bfseries{Growing (new\+\_\+bytes $>$ current block capacity)\+:}}
\begin{DoxyItemize}
\item Allocates new larger block via \mbox{\hyperlink{classcslt_1_1BuddyAllocator_ad73ade6bd9d847cf670eef2acb1a5258}{alloc()}}
\item Copies min(old\+\_\+bytes, usable\+\_\+old) bytes to new block
\item Frees old block (triggers coalescing)
\item Returns new pointer (old pointer becomes invalid)
\item If new allocation fails, old pointer remains valid
\end{DoxyItemize}

{\bfseries{Block Capacity\+:}} The usable capacity of a block is determined by its order (power-\/of-\/2 size) minus the header. For example, a block with order=8 (256 bytes) has 240 bytes usable (256 -\/ 16 byte header).

{\bfseries{Data Preservation\+:}} When growing, all data from the old allocation is copied to the new one. The copy size is min(old\+\_\+bytes, actual\+\_\+usable\+\_\+capacity) to prevent reading beyond the old allocation.

\begin{DoxyNote}{Note}
The returned pointer may be different from the input pointer, even when shrinking. Always use the returned pointer.

When growing fails, the old pointer remains valid and unchanged. This provides transactional semantics -\/ the operation either succeeds completely or leaves the allocation in its original state.

old\+\_\+bytes is used to determine how much data to preserve when growing. Providing an incorrect value may result in data loss or reading invalid memory.
\end{DoxyNote}

Resize an existing allocation while preserving alignment. 


\begin{DoxyParams}{Parameters}
{\em ptr} & Pointer to existing allocation (or nullptr) \\
\hline
{\em old\+\_\+bytes} & Current size of the allocation in bytes \\
\hline
{\em new\+\_\+bytes} & Desired new size in bytes \\
\hline
{\em alignment} & Required alignment in bytes (0 = alignof(max\+\_\+align\+\_\+t), will be rounded up to power of 2) \\
\hline
{\em zeroed} & If true, zero-\/initialize any newly allocated space (when growing)\\
\hline
\end{DoxyParams}
\begin{DoxyReturn}{Returns}
\mbox{\hyperlink{classcslt_1_1Expected}{Expected}} containing pointer to resized aligned allocation on success, or error on failure
\end{DoxyReturn}
Resizes an existing allocation while maintaining alignment guarantees. Behaves similarly to \mbox{\hyperlink{classcslt_1_1BuddyAllocator_aa30b5019edd20f34bd42c46cd27bb6b9}{realloc()}} but with additional alignment handling.

{\bfseries{Special Cases\+:}}
\begin{DoxyItemize}
\item realloc\+\_\+aligned(nullptr, 0, n, a) → Equivalent to alloc\+\_\+aligned(n, a)
\item realloc\+\_\+aligned(ptr, old, 0, a) → Frees ptr, returns nullptr (success)
\item realloc\+\_\+aligned(ptr, 0, n, a) → \mbox{\hyperlink{classcslt_1_1Error}{Error}} (old\+\_\+bytes must be non-\/zero)
\end{DoxyItemize}

{\bfseries{In-\/\+Place Reuse (no reallocation)\+:}} Occurs when ALL of these conditions are met\+:
\begin{DoxyItemize}
\item new\+\_\+bytes fits in current block capacity
\item ptr already satisfies the requested alignment Returns same pointer, very fast (O(1))
\end{DoxyItemize}

{\bfseries{Reallocation Required\+:}} Occurs when ANY of these is true\+:
\begin{DoxyItemize}
\item new\+\_\+bytes exceeds current block capacity
\item ptr doesn\textquotesingle{}t satisfy requested alignment (alignment changed) Allocates new block with \mbox{\hyperlink{classcslt_1_1BuddyAllocator_a80193b4cc99ced2e692cf324df4f994b}{alloc\+\_\+aligned()}}, copies data, frees old block
\end{DoxyItemize}

{\bfseries{Alignment Changes\+:}} You can change alignment during realloc. For example, reallocating from 32-\/byte to 64-\/byte alignment will trigger a new allocation even if the size fits in the current block.

{\bfseries{Data Preservation\+:}} When reallocating, copies min(old\+\_\+bytes, actual\+\_\+usable\+\_\+capacity) bytes to preserve all data from the old allocation.

\begin{DoxyNote}{Note}
alignment is normalized to a power of 2. Requesting 48 will be rounded to 64.

The returned pointer may be different from the input pointer. Always use the returned pointer and consider the old pointer invalid.

When growing fails, the old pointer remains valid and unchanged.

Changing alignment (even to a less strict value) may trigger reallocation.
\end{DoxyNote}

Query the number of bytes currently available for allocation. 

\begin{DoxyReturn}{Returns}
Number of free bytes remaining in the allocator\textquotesingle{}s memory pool
\end{DoxyReturn}
Returns the difference between the total pool size and the number of bytes currently allocated. This represents the {\itshape aggregate} free capacity and does NOT account for fragmentation.

As a result, it is possible for \mbox{\hyperlink{classcslt_1_1BuddyAllocator_a1a05d4c28353926c6029ecd0f9f2080d}{remaining()}} to return a non-\/zero value even when a large allocation cannot be satisfied due to fragmentation.

This function is constant-\/time and does not modify allocator state.

\begin{DoxyNote}{Note}
To determine the maximum single allocation that can currently succeed, use \mbox{\hyperlink{classcslt_1_1BuddyAllocator_abd0fddad8adb07f77464d53c39ba41d7}{largest\+\_\+block()}} instead.

{\footnotesize\ttfamily bool cslt\+::\+Buddy\+Allocator\+::reset (\begin{DoxyParamCaption}\item[{bool}]{trim = {\ttfamily false} }\end{DoxyParamCaption})\hspace{0.3cm}{\ttfamily [override]}, {\ttfamily [virtual]}}



Reset allocator to initial state, freeing all allocations. 


\begin{DoxyParams}{Parameters}
{\em trim} & Ignored (present for interface compatibility)\\
\hline
\end{DoxyParams}
\begin{DoxyReturn}{Returns}
true on success, false if allocator is not properly initialized
\end{DoxyReturn}
Resets the buddy allocator to its pristine initial state by clearing all free lists and placing a single large free block spanning the entire pool at the top level.

{\bfseries{Reset Process\+:}}
\begin{DoxyEnumerate}
\item Validate allocator is initialized (base, pool\+\_\+size, num\+\_\+levels valid)
\item Clear all free lists (set all levels to nullptr)
\item Create initial free block at pool base
\item Place block in top-\/level free list (max\+\_\+order)
\item Reset accounting (size\+\_\+ = 0)
\end{DoxyEnumerate}

{\bfseries{Effect\+:}}
\begin{DoxyItemize}
\item All previous allocations become invalid
\item Memory pool returns to single large free block
\item All fragmentation eliminated
\item \mbox{\hyperlink{classcslt_1_1Allocator}{Allocator}} ready for reuse
\end{DoxyItemize}

{\bfseries{Performance\+:}} O(n) where n is the number of free list levels, but typically very fast since it just clears an array and sets a few pointers.

{\bfseries{Use Cases\+:}}
\begin{DoxyItemize}
\item Bulk cleanup faster than freeing individually
\item Per-\/frame allocations in game engines
\item Request/response cycle allocations in servers
\item Temporary computation scratch space
\item Test cleanup between test cases
\end{DoxyItemize}

\begin{DoxyNote}{Note}
The trim parameter is ignored by \mbox{\hyperlink{classcslt_1_1BuddyAllocator}{Buddy\+Allocator}}. The pool size is fixed and cannot be trimmed. The parameter exists for interface compatibility.

All outstanding pointers become invalid after \mbox{\hyperlink{classcslt_1_1BuddyAllocator_aa923e1e70ca1361b07780e973d0bc298}{reset()}}. Accessing them results in undefined behavior.

The OS-\/backed memory pool is NOT freed. \mbox{\hyperlink{classcslt_1_1BuddyAllocator_aa923e1e70ca1361b07780e973d0bc298}{reset()}} only clears the internal free list structure. To free OS memory, destroy the \mbox{\hyperlink{classcslt_1_1BuddyAllocator}{Buddy\+Allocator}}.

\mbox{\hyperlink{classcslt_1_1BuddyAllocator_aa923e1e70ca1361b07780e973d0bc298}{reset()}} is much faster than individually freeing many allocations, especially when there are hundreds or thousands of active allocations.
\end{DoxyNote}
\begin{DoxyWarning}{Warning}
After \mbox{\hyperlink{classcslt_1_1BuddyAllocator_aa923e1e70ca1361b07780e973d0bc298}{reset()}}, ALL pointers obtained from this allocator become invalid. Ensure no code will access these pointers after calling \mbox{\hyperlink{classcslt_1_1BuddyAllocator_aa923e1e70ca1361b07780e973d0bc298}{reset()}}.
\end{DoxyWarning}

{\footnotesize\ttfamily void cslt\+::\+Buddy\+Allocator\+::return\+\_\+element (\begin{DoxyParamCaption}\item[{void $\ast$}]{ptr,  }\item[{size\+\_\+t}]{bytes = {\ttfamily 0},  }\item[{size\+\_\+t}]{alignment = {\ttfamily 0} }\end{DoxyParamCaption})\hspace{0.3cm}{\ttfamily [override]}, {\ttfamily [virtual]}}



Free an allocated block and trigger buddy coalescing. 


\begin{DoxyParams}{Parameters}
{\em ptr} & Pointer to free (returned from alloc, alloc\+\_\+aligned, realloc, or realloc\+\_\+aligned) \\
\hline
{\em bytes} & Ignored (present for interface compatibility) \\
\hline
{\em alignment} & Ignored (present for interface compatibility)\\
\hline
\end{DoxyParams}
Frees a previously allocated block and attempts to coalesce (merge) it with its buddy block to form larger free blocks. This is the core deallocation mechanism of the buddy allocator.

{\bfseries{Deallocation Process\+:}}
\begin{DoxyEnumerate}
\item Validate pointer is not null (null is silently ignored)
\item Read Buddy\+Header located 16 bytes before the user pointer
\item Validate header (order within valid range, offset within pool)
\item Calculate block start from header\textquotesingle{}s block\+\_\+offset
\item Update accounting (decrease size\+\_\+)
\item Begin coalescing process
\end{DoxyEnumerate}

{\bfseries{Coalescing Algorithm\+:}} The allocator recursively merges blocks with their buddies\+:
\begin{DoxyEnumerate}
\item Calculate buddy offset\+: current\+\_\+offset XOR (2$^\wedge$current\+\_\+order)
\item Check if buddy is in the free list at this level
\item If buddy is free\+:
\begin{DoxyItemize}
\item Remove buddy from free list
\item Merge with current block (use lower address)
\item Increase order (double the size)
\item Repeat at next level
\end{DoxyItemize}
\item If buddy is NOT free (still allocated)\+:
\begin{DoxyItemize}
\item Stop coalescing
\item Insert current block into appropriate free list
\end{DoxyItemize}
\end{DoxyEnumerate}

{\bfseries{Coalescing Example\+:}} 
\begin{DoxyCode}{0}
\DoxyCodeLine{Pool: 1024 bytes (order 10)}
\DoxyCodeLine{}
\DoxyCodeLine{Free block at offset 0, order 7 (128 bytes):}
\DoxyCodeLine{  Buddy at offset: 0 XOR 128 = 128}
\DoxyCodeLine{  If buddy at 128 is free:}
\DoxyCodeLine{    Merge → 256-\/\textcolor{keywordtype}{byte} block at offset 0, order 8}
\DoxyCodeLine{    }
\DoxyCodeLine{  New buddy at: 0 XOR 256 = 256}
\DoxyCodeLine{  If buddy at 256 is free:}
\DoxyCodeLine{    Merge → 512-\/\textcolor{keywordtype}{byte} block at offset 0, order 9}
\DoxyCodeLine{    }
\DoxyCodeLine{  Continue until buddy not free or reach max\_order}

\end{DoxyCode}


{\bfseries{Performance\+:}} O(log n) where n is the number of size levels, due to recursive coalescing up the buddy tree.

\begin{DoxyNote}{Note}
The bytes and alignment parameters are ignored by \mbox{\hyperlink{classcslt_1_1BuddyAllocator}{Buddy\+Allocator}}. They exist only for base class interface compatibility. The allocator determines block size from the internal header.

Passing nullptr is safe and does nothing (similar to free(nullptr)).

Invalid pointers (wrong allocator, already freed, corrupted header) are handled silently. The function returns without error but may not free the memory correctly.

Double-\/free results in undefined behavior. The allocator may detect some cases via header validation but cannot catch all scenarios.

After this call, ptr becomes invalid. Accessing it results in undefined behavior.
\end{DoxyNote}
\begin{DoxyWarning}{Warning}
Do not free pointers from a different \mbox{\hyperlink{classcslt_1_1BuddyAllocator}{Buddy\+Allocator}} instance. Each allocator manages its own distinct pool.

Do not modify the memory before the returned pointer. The header region must remain intact for proper deallocation.
\end{DoxyWarning}

Generate a human-\/readable summary of allocator state. 


\begin{DoxyParams}{Parameters}

\begin{DoxyReturn}{Returns}
true if statistics were successfully written to {\ttfamily buffer}, false if an error occurred (e.\+g., invalid buffer or insufficient space)

Writes a textual report describing the current state of the \mbox{\hyperlink{classcslt_1_1BuddyAllocator}{Buddy\+Allocator}} into the user-\/provided buffer. The report includes\+:


\begin{DoxyItemize}
\item Total pool size
\item Minimum and maximum block sizes
\item Currently allocated bytes
\item Remaining free capacity
\item Largest available free block
\item Overall utilization percentage
\item Per-\/level free list statistics (block count and free bytes)
\end{DoxyItemize}

The output is intended for diagnostics, debugging, and monitoring. The exact formatting is implementation-\/defined but stable enough for human consumption.

This function performs no allocations and does not modify allocator state.

\begin{DoxyNote}{Note}
If {\ttfamily buffer} is null or {\ttfamily buffer\+\_\+size} is zero, the function returns false and no output is produced.

If the buffer is too small to hold the full report, the function returns false. Partial output may have been written to {\ttfamily buffer}.

The statistics represent a snapshot at the time of the call and may become stale immediately in multi-\/threaded environments.
\end{DoxyNote}
