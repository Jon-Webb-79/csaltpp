\doxysubsection{Detailed Description}
Variable-\/size block allocator with automatic coalescing to reduce fragmentation. 

\mbox{\hyperlink{classcslt_1_1FreeListAllocator}{Free\+List\+Allocator}} manages variable-\/sized allocations from a contiguous memory region using a linked list of free blocks. Unlike \mbox{\hyperlink{classcslt_1_1PoolAllocator}{Pool\+Allocator}} which handles fixed-\/size blocks, \mbox{\hyperlink{classcslt_1_1FreeListAllocator}{Free\+List\+Allocator}} can allocate blocks of any size up to available capacity. Freed blocks are automatically coalesced with adjacent free blocks to reduce external fragmentation.

Each allocated block carries a small header storing its size and alignment offset. Free blocks maintain a linked list for efficient reuse. The allocator uses a best-\/fit search strategy to find suitable free blocks.

Allocates a block of the requested size from the freelist using a first-\/fit search strategy. The allocator searches the free list for the first block large enough to satisfy the request, accounting for alignment padding and header overhead.

Internally, this delegates to \mbox{\hyperlink{classcslt_1_1FreeListAllocator_a683d799ad03202bc7b6aef3ad020d2e8}{alloc\+\_\+aligned()}} using the freelist\textquotesingle{}s default alignment. Each allocated block carries a small header (Free\+List\+Header) storing its total size and offset for proper deallocation.

If a free block is larger than needed, it may be split into an allocated portion and a new smaller free block. If the remainder would be too small ($<$ sizeof(\+Free\+Block)), the entire block is consumed to avoid creating unusable fragments.

\begin{DoxyNote}{Note}
The actual memory consumed may exceed \textquotesingle{}bytes\textquotesingle{} due to\+:
\begin{DoxyItemize}
\item Free\+List\+Header (stored before user pointer)
\item Alignment padding
\item Full block consumption when remainder is too small
\end{DoxyItemize}

Allocated blocks must be returned via \mbox{\hyperlink{classcslt_1_1FreeListAllocator_a92297e3568123854b9c2ea7398f4058f}{return\+\_\+element()}} for reuse. Adjacent freed blocks are automatically coalesced to reduce fragmentation.
\end{DoxyNote}
\begin{DoxyWarning}{Warning}
Passing bytes larger than available capacity will fail. Check \mbox{\hyperlink{classcslt_1_1FreeListAllocator_a59626d72b6725ad3012c06bc9b1069e4}{remaining()}} before large allocations if needed.
\end{DoxyWarning}

Allocates a block of the requested size with the specified alignment. The allocator searches the free list for a block large enough to accommodate\+:
\begin{DoxyItemize}
\item Free\+List\+Header metadata
\item Alignment padding to satisfy the alignment requirement
\item The requested user bytes
\end{DoxyItemize}

The returned pointer is guaranteed to be aligned to at least the requested alignment (or the freelist\textquotesingle{}s default alignment, whichever is greater). Alignment padding increases internal fragmentation but ensures correct data alignment for hardware requirements.

If the requested alignment is 0 or less than the freelist\textquotesingle{}s default, the default alignment is used. Non-\/power-\/of-\/two alignments are rounded up to the next power of 2.

\begin{DoxyNote}{Note}
Stricter alignment may consume significantly more memory due to padding. For example, a 64-\/byte allocation with 256-\/byte alignment may consume up to $\sim$320 bytes total.

The allocated block must be freed via \mbox{\hyperlink{classcslt_1_1FreeListAllocator_a92297e3568123854b9c2ea7398f4058f}{return\+\_\+element()}}, not free().
\end{DoxyNote}
\begin{DoxyWarning}{Warning}
Requesting alignment stricter than the freelist\textquotesingle{}s base alignment increases fragmentation and reduces effective capacity.
\end{DoxyWarning}

Resizes an allocation following standard \mbox{\hyperlink{classcslt_1_1FreeListAllocator_af100ec762c3ebda5e255af32e4ba594d}{realloc()}} semantics\+: \begin{DoxyVerb}     **NULL pointer**: Behaves like alloc(new_bytes, zeroed)

     **Shrink or same size** (new_bytes <= old_bytes):
     - Returns the original pointer unchanged
     - No memory is freed or reallocated
     - Freelist does not support in-place shrinking

     **Grow** (new_bytes > old_bytes):
     1. Allocates new block of new_bytes
     2. Copies first old_bytes from old block to new block
     3. Zero-fills [old_bytes, new_bytes) if zeroed == true
     4. Returns old block to freelist via return_element()
     5. Returns pointer to new block

     The freelist never performs in-place growth; all expansions require
     allocate-copy-free semantics. This ensures proper alignment and
     allows coalescing of the old block.
\end{DoxyVerb}
 \begin{DoxyNote}{Note}
Growth always allocates a new block -\/ the returned pointer will be different from the original when new\+\_\+bytes $>$ old\+\_\+bytes.

The caller must track old\+\_\+bytes accurately. Incorrect values may result in data corruption (too small) or invalid memory access (too large).

Old pointer becomes invalid after successful growth. Do not use it.
\end{DoxyNote}
\begin{DoxyWarning}{Warning}
Passing incorrect old\+\_\+bytes can corrupt data or crash. The freelist cannot validate the size parameter.
\end{DoxyWarning}

Get the number of bytes available for new allocations. 

\begin{DoxyReturn}{Returns}
Number of bytes remaining for allocation
\end{DoxyReturn}
Returns the number of bytes currently available for new allocations, calculated as (capacity -\/ used). This represents the logical free space, accounting for all overhead including headers and alignment padding that has been consumed by existing allocations.

Note that the actual usable space for a new allocation may be less than this value due to\+:
\begin{DoxyItemize}
\item Fragmentation (free space split across multiple small blocks)
\item Alignment requirements for the new allocation
\item Per-\/allocation header overhead (Free\+List\+Header)
\end{DoxyItemize}

\begin{DoxyNote}{Note}
This is a logical capacity measure, not a guarantee that an allocation of this size will succeed. Use \mbox{\hyperlink{classcslt_1_1FreeListAllocator_a90a7d9f260434769fefd96bffc592fc2}{is\+\_\+ptr\+\_\+sized()}} to validate actual allocation feasibility.

The value equals capacity() immediately after construction or \mbox{\hyperlink{classcslt_1_1FreeListAllocator_a51baa0c6eb9df1a576b63237ad226bf3}{reset()}}.
\end{DoxyNote}

Reset freelist to initial empty state. 


\begin{DoxyParams}{Parameters}
{\em trim} & Unused for freelists (for interface compatibility). Freelists do not trim or release memory back to the system.\\
\hline
\end{DoxyParams}
\begin{DoxyReturn}{Returns}
true if reset succeeded, false if freelist is not initialized
\end{DoxyReturn}
Resets the freelist to its initial pristine state, as if freshly created. All allocation state is cleared and the entire usable region is rebuilt as a single large free block.

The reset operation\+:
\begin{DoxyEnumerate}
\item Clears usage accounting (len\+\_\+ = 0, size\+\_\+ = 0)
\item Resets high-\/water mark (cur\+\_\+ = memory\+\_\+)
\item Destroys free list
\item Creates single free block spanning entire region
\end{DoxyEnumerate}

This is an O(1) operation regardless of how many allocations exist or how fragmented the freelist has become. No memory is freed back to the operating system; the freelist retains its capacity.

\begin{DoxyNote}{Note}
All outstanding allocations become invalid immediately. Any pointers obtained before \mbox{\hyperlink{classcslt_1_1FreeListAllocator_a51baa0c6eb9df1a576b63237ad226bf3}{reset()}} must not be used after \mbox{\hyperlink{classcslt_1_1FreeListAllocator_a51baa0c6eb9df1a576b63237ad226bf3}{reset()}}.

The freelist is immediately ready for new allocations after \mbox{\hyperlink{classcslt_1_1FreeListAllocator_a51baa0c6eb9df1a576b63237ad226bf3}{reset()}}. There is no fragmentation -\/ the entire capacity is available as one contiguous block.

No memory is released. The backing arena remains unchanged.
\end{DoxyNote}
\begin{DoxyWarning}{Warning}
Invalidates ALL outstanding pointers. Ensure no code holds pointers across a \mbox{\hyperlink{classcslt_1_1FreeListAllocator_a51baa0c6eb9df1a576b63237ad226bf3}{reset()}} call.
\end{DoxyWarning}

This method is implemented to satisfy the \mbox{\hyperlink{classcslt_1_1Allocator}{Allocator}} base class interface contract but is not supported for \mbox{\hyperlink{classcslt_1_1FreeListAllocator}{Free\+List\+Allocator}}.

\mbox{\hyperlink{classcslt_1_1FreeListAllocator}{Free\+List\+Allocator}} cannot support checkpoint/restore semantics because\+:
\begin{DoxyItemize}
\item The free list structure uses embedded pointers that would be invalidated
\item Allocation headers contain metadata that cannot be simply discarded
\item User pointers to \char`\"{}restored away\char`\"{} allocations would become dangling
\item No efficient way to track which allocations to invalidate
\end{DoxyItemize}

For resetting the allocator state, use \mbox{\hyperlink{classcslt_1_1FreeListAllocator_a51baa0c6eb9df1a576b63237ad226bf3}{reset()}} which clears all allocations and returns the freelist to pristine condition.

\begin{DoxyNote}{Note}
This is a no-\/op implementation. The checkpoint parameter is ignored and the method always returns false.

Attempting to use checkpoints from other allocator types will fail safely (returns false) but should be avoided.
\end{DoxyNote}

\begin{DoxyParams}{Parameters}

{\em alignment} & Alignment parameter (unused for freelists, for interface compatibility).\\

Returns an allocated block to the freelist, making it available for future allocations. The freelist automatically coalesces the freed block with adjacent free blocks to reduce external fragmentation.

The method performs extensive validation\+:
\begin{DoxyEnumerate}
\item Pointer is within freelist memory region
\item Valid Free\+List\+Header exists before the pointer
\item Block size and offset are sane
\item Block fits within freelist bounds
\end{DoxyEnumerate}

The freed block is inserted into the free list in address order, then coalesced with adjacent blocks\+:
\begin{DoxyItemize}
\item {\bfseries{Forward coalescing}}\+: Merges with next block if adjacent
\item {\bfseries{Backward coalescing}}\+: Merges with previous block if adjacent
\end{DoxyItemize}

Coalescing prevents fragmentation by combining small free blocks into larger contiguous regions.

\begin{DoxyNote}{Note}
The bytes and alignment parameters are ignored. \mbox{\hyperlink{classcslt_1_1FreeListAllocator}{Free\+List\+Allocator}} retrieves size information from the block\textquotesingle{}s header.

This method is silent on invalid pointers -\/ it returns without error if validation fails. This is defensive programming to prevent crashes.

Double-\/freeing the same pointer is detected and ignored safely.
\end{DoxyNote}
\begin{DoxyWarning}{Warning}
After calling this method, ptr becomes invalid and must not be dereferenced. Any attempt to use the pointer results in undefined behavior.

Passing a pointer from a different allocator results in undefined behavior. Only return pointers allocated from this freelist.
\end{DoxyWarning}

This method is implemented to satisfy the \mbox{\hyperlink{classcslt_1_1Allocator}{Allocator}} base class interface contract but is not supported for \mbox{\hyperlink{classcslt_1_1FreeListAllocator}{Free\+List\+Allocator}}.

Unlike \mbox{\hyperlink{classcslt_1_1ArenaAllocator}{Arena\+Allocator}} and \mbox{\hyperlink{classcslt_1_1PoolAllocator}{Pool\+Allocator}} which support checkpointing, \mbox{\hyperlink{classcslt_1_1FreeListAllocator}{Free\+List\+Allocator}} cannot provide meaningful checkpoint/restore functionality because\+:
\begin{DoxyItemize}
\item Free blocks are managed via a linked list with pointers
\item Allocation metadata is interleaved with user data
\item Restoring would require tracking all allocation headers
\item No clear way to invalidate user pointers to restored allocations
\end{DoxyItemize}

For bulk cleanup of all allocations, use \mbox{\hyperlink{classcslt_1_1FreeListAllocator_a51baa0c6eb9df1a576b63237ad226bf3}{reset()}} instead, which returns the freelist to its initial empty state.

\begin{DoxyNote}{Note}
This is a no-\/op implementation. Always returns nullptr.

If checkpoint/restore functionality is needed, consider using \mbox{\hyperlink{classcslt_1_1ArenaAllocator}{Arena\+Allocator}} or \mbox{\hyperlink{classcslt_1_1PoolAllocator}{Pool\+Allocator}} instead.
\end{DoxyNote}

Constructs a freelist entirely within a caller-\/provided memory buffer. No heap allocation is performed. The freelist does NOT take ownership of the buffer; the caller is responsible for ensuring that the buffer remains valid for the full lifetime of the freelist.

Internally, this creates a non-\/owning STATIC arena over the supplied buffer and then carves the freelist allocator from that arena. The freelist owns the arena object but not the underlying buffer.

\begin{DoxyNote}{Note}
The freelist does NOT own the buffer. Destroying or resetting the freelist does not free the buffer.

Well suited for embedded systems, scratch allocators, or environments where dynamic allocation is restricted.
\end{DoxyNote}

Generates a human-\/readable, multi-\/line text report describing the internal state of the freelist allocator. The report includes\+:


\begin{DoxyItemize}
\item {\bfseries{Type}}\+: STATIC or DYNAMIC (inherited from backing arena)
\item {\bfseries{Ownership}}\+: Whether the freelist owns its arena
\item {\bfseries{Memory accounting}}\+: Used bytes, remaining bytes, capacity
\item {\bfseries{Overhead}}\+: Total size including headers
\item {\bfseries{Utilization}}\+: Percentage of capacity currently in use
\item {\bfseries{Alignment}}\+: Base alignment for allocations
\item {\bfseries{Free list}}\+: Enumeration of all free blocks with addresses and sizes
\end{DoxyItemize}

The report is written using internal {\ttfamily \mbox{\hyperlink{namespacecslt_a60929310f6258747143b37bbebb0d22e}{\+\_\+buf\+\_\+appendf()}}} utility which safely handles buffer overflow. Output is always null-\/terminated as long as buffer\+\_\+size $>$= 1.

This method is useful for debugging, logging, performance analysis, and verification during development. It provides insight into fragmentation, capacity utilization, and memory layout.

\begin{DoxyNote}{Note}
If the buffer is too small, the report will be truncated but still null-\/terminated and safe to use.

This method does not allocate memory -\/ all output uses the provided buffer.
\end{DoxyNote}
\begin{DoxyWarning}{Warning}
Large freelists with many free blocks may produce output exceeding typical buffer sizes. Consider using a 2KB or larger buffer for detailed reports.
\end{DoxyWarning}

Get the number of bytes currently consumed by allocations. 

\begin{DoxyReturn}{Returns}
Number of bytes currently in use (including internal overhead)
\end{DoxyReturn}
Returns the total number of bytes consumed by current allocations, including all internal overhead such as\+:
\begin{DoxyItemize}
\item Free\+List\+Header metadata for each allocated block
\item Alignment padding between headers and user data
\item Full block consumption when remainders are too small to split
\end{DoxyItemize}

This is the internal accounting value (len\+\_\+) which tracks the total size charged for all outstanding allocations. It increases with each \mbox{\hyperlink{classcslt_1_1FreeListAllocator_aa290f402dabf95b51f352235c77809ed}{alloc()}} call and decreases with each \mbox{\hyperlink{classcslt_1_1FreeListAllocator_a92297e3568123854b9c2ea7398f4058f}{return\+\_\+element()}} call.

The value may be significantly larger than the sum of user-\/requested allocation sizes due to internal overhead. For example, a 256-\/byte allocation might consume 280+ bytes when accounting for header and alignment padding.

\begin{DoxyNote}{Note}
This is the total block size consumed, not just user-\/visible bytes. It includes all metadata and padding.

Returns 0 immediately after construction or \mbox{\hyperlink{classcslt_1_1FreeListAllocator_a51baa0c6eb9df1a576b63237ad226bf3}{reset()}}.

Creates a freelist within an existing arena\textquotesingle{}s memory space. The freelist does NOT own the arena -\/ the caller or another component is responsible for the arena\textquotesingle{}s lifetime. Multiple allocators can share the same arena for efficient memory use.

The freelist inherits its memory type (STATIC/\+DYNAMIC) from the parent arena. When the freelist is destroyed, the arena remains valid and usable by other allocators.

\begin{DoxyNote}{Note}
Arena must remain valid for the freelist\textquotesingle{}s entire lifetime.

The freelist does NOT own the arena. Destroying the freelist does not affect the arena.
\end{DoxyNote}

Destroying the arena while freelists still reference it results in undefined behavior.
